# Deviations from ThreeUI

1. **pinned revision unavailable; current canonical source used.** Authorized by the user. The JSON bundle's HTML metadata is stale and it has no embedded HTML copy. Its referenced canonical URL is used with the separately authorized actual hash. See SOURCE.md.
2. **Direct source import.** The package does not ship Kibori. The component is imported locally and the exact shared CSS is imported from vendor/threeui. React, React DOM, and the scene's exact Three.js 0.169.0 are the only runtime packages.
3. **Content substitutions.** `scripts/prepare-portfolio.mjs` derives the hero, eight chapter headings/descriptions/metadata, index labels, inspector English labels, and finale from `src/portfolio-data.json`. Japanese text is retained unchanged as decoration. The three real projects are grouped into eight perspectives. All source geometry, shaders, physics, fire, scroll/glide logic, camera poses, and authored reduced-motion logic remain intact.
4. **Disable one wood-strip copy write.** The canonical line that replaces chapter 1's second metadata field with the lattice member count is removed in the generated copy. It would otherwise overwrite the verified “Rich CLI” project metadata. The geometry count itself is unchanged.
5. **Local dependency and asset URLs.** The canonical's Supabase hash URLs are mapped to the original registered kibori-assets paths with identical bytes. The import map and preload now use the local exact npm Three.js build. These resources no longer require third-party fetches at runtime. No new photographic imagery or fabricated project screenshots are used.
6. **Working contact actions.** The demo-only “nowhere to send it” handler becomes an explicit mailto draft action. Validation stays in place; no automatic sending or success claim is added. Original Kyoto business details and response-time promises become real supplied contact links, location, education, and social links. The source resume is offered unchanged and labelled historical.
7. **Supplementary portfolio index.** The finale keeps the authored paper, artwork, form, and layout, and adds one data-driven section for project summaries, skills, education, experience placeholder, coursework, and certifications. An additional named grid area places it before the footer base on desktop and mobile.
8. **Accessibility.** Project source links and “Explore craft” buttons are added to chapters. Buttons call the original inspectOpen function; arrow keys turn the same object. Opening an inspector focuses Close, Escape retains the authored handler, and closing restores focus. Visible focus rings, descriptive iframe labels, and a labelled hero heading are added. Original reduced-motion behavior is retained; added controls avoid animation under reduced motion.
9. **Content fit.** A separate portfolio.css adjusts project title sizing, long metadata, mobile branding, and footer text wrapping. It does not replace the source stylesheet. The original responsive scene framing and transitions are retained.
10. **Iframe permissions.** The registered component's title/ARIA label becomes the portfolio's identity. Its script sandbox also permits form events, user-initiated external links, downloads, and mailto navigation. Form events are necessary for the email validation/draft handler; it prevents network submission. Same-origin access remains disabled; Vite/Vercel CORS headers permit the local font/image/module resources inside the sandbox. The later visibility-lifecycle adaptation is described in item 15.
11. **Metadata and project shell.** Vite + React + TypeScript replace the legacy Next.js project as requested. The page shell and generated scene contain portfolio title, description, theme, and Open Graph metadata. Git attributes preserve pristine source and asset hashes across Windows checkouts.

12. **Responsive follow-up.** The content stylesheet now uses fluid width/height-based type, safe-area insets, 44px action targets, a one-column contact form below 400px, bounded copy scrolling on short displays, and constrained ultrawide text. The outer shell includes a legacy viewport-height fallback. Scene geometry and render-quality caps remain authored.
13. **Orientation continuity.** The generated resize function preserves normalized story progress when dimensions change. Glyph measurement is refreshed after height-only changes as well as width changes, because the responsive typography now depends on both. These are isolated guarded substitutions; the pristine source is unchanged.

14. **Faster kindling/startup (2026-11-11).** `scripts/startup-adapter.mjs` gates the original all-material compilation and 48 off-screen station renders behind the explicit scene-document query `?warmup=full`. Normal entry starts the original frame loop directly, allowing Three.js to compile materials on first use. No geometry, shader, pixel ratio, or render-quality cap is changed. Later first-use compilation may hitch. Local readiness diagnostics record phase timings after the real loader is removed; no telemetry is transmitted. Vercel receives immutable cache headers only for the verified, unchanged registered assets.

15. **Avoid repeat kindling on browser-tab return (2026-11-11).** The host no longer unmounts the iframe solely because `document.hidden` changed. It retains the loaded scene while the browser throttles hidden frames and still exposes a paused indicator. Intersection-based unmounting remains. Full reloads and actual unmounts still rebuild the workshop.

The unmodified upstream inputs remain in vendor/threeui. The generated public HTML is ignored by Git and reproduced on every dev/build invocation. `docs/generated-source.json` records the generated artifact, adapted component, responsive CSS, and shell CSS digests in addition to pristine inputs.
